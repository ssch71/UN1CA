  Only1x/2x lens positions and continuous intermediate zoom are exposed;3x and
  second-tele shortcuts are skipped in the rear seamless UI. The optical3x
  button is intentionally unavailable during this baseline.
  Camera23 PORTRAIT bounds are restricted to1..2, matching the inspected

  Rear session setup starts at1x, ignoring saved Portrait zoom and the old3x

  Existing Dual Recording patches remain applied. No native provider library,

Runtime acceptance gates -- required before extending to3x
  1. Build/flash through the normal ROM workflow. Do not clear Camera data.
     Open rear Photo Portrait. It must initialize at1x even if the prior ROM
     remembered3x. Confirm1x/2x controls and no3x/10x control in this baseline.
  2. Use a stationary subject with a detailed background and adequate light.
     Begin with flash off and ordinary Portrait, without Night processing, to
     isolate the base path. Capture at1x first. Stop if Camera reports an error.
  3. Move smoothly1 ->1.25 ->1.5 ->1.75 ->2x, then back to1x. Capture at1x,
     1.5x and2x. Logical23 and its main56/sub58 pair must remain selected.
     A pair configuration log alone does not prove both cameras became active;
     inspect available provider state/result evidence and successful depth.
  4. Compare preview versus saved framing, subject boundaries and blur strength.
     Check Gallery Portrait blur adjustment/depth editing where offered. A
     saved ordinary photo, mismatched framing or broken depth is a failed gate.
  5. Leave Portrait at2x, reopen it, and confirm a fresh1x session. Repeat after
     switching rear/front. Regress normal Photo, Video and Dual Recording.
  6. Any provider abort, CHI recovery, zero active mask, invalid master/history,
     camera-ID switch, or capture/depth mismatch fails the baseline. Keep3x
     disabled; reset-only behavior is not evidence that the state bug is fixed.

Wide-only1..3x investigation update -- 2026-11-08
  The user's target is now continuous framing on wide56+58 only. Neither10x
  static depth nor a telephoto handoff is required for this narrower design.
  That does not make the failed UI/provider crop implementation usable.

  Confirmed native barriers, all static rather than new runtime results:
  - RTB GetZoomRatio normalizes intermediate>1 values except exact2 to1.
  - RTB crop helper feeds face/focus ROI transforms. Changing it alone is not
    established output framing. Zoom travels through EXTRA_BUFFER_INFO0x0c.
  - Stock LiveFocusPreview DiamondParam::is_zoom_level_changed returns0.
    Preview Process has a virtual-call-controlled reinitialization path; a
    zoom clamp patch alone cannot establish coherent changing geometry.
  - New app v1_1 JNI crop commands0x2a/0x2b are rejected by stock capture plugin
    set_plugin's maximum0x29 check. Prior Java setCropRegionInfo availability
    was insufficient evidence for working native crop support. Donor0x2a/2b
    carry different meanings, so donor index handlers cannot be copied blindly.
  - ARC_DCIR_CropResizeImg exists in stock depth engine, ELF0x1c4c57c. It
    creates a plane-offset crop view and invokes resize. It does not by itself
    establish cropping the proprietary disparity payload or Gallery metadata.

  Smallest credible implementation route:
  1. Keep camera23 physical56+58 at its validated base1x request/input geometry.
     Separate requested output zoom from provider lens-selection zoom. No3x
     request may reach the previously failing state transition path merely
     because the application slider is allowed to reach3x.
  2. Implement an exact-version compatible output adapter after calibrated
     processing: same visible image/preview frame, registered depth coordinate
     domain, face/focus/metering ROI transforms and saved refocus payload.
     Existing full-array inputs must not be center-cropped independently.
  3. Trace native crop normalization/resize limits and exact render/depth export
     representation before using CropResizeImg. Do not treat NV21 scaling as
     an implementation for a proprietary disparity blob. Respect chroma edges,
     output buffer lifetimes, orientation and any padding/valid-region limits.
  4. Add a diagnostic output-only zoom sweep1,1.25,1.5,2,2.5,3 and back while
     recording base provider requests. Require stable two-state/master/history,
     preview-versus-saved framing, real blur boundaries and Gallery refocus.
     Reopen at every value and confirm normal Photo/Video behavior afterward.

  No new working in-Camera crop adapter or usable1..3x Portrait is claimed.
  Keep0006/0007 and SUPPORT_PORTRAIT_SEAMLESS_ZOOM disabled. Native wrappers,
  preview renderer and saved Portrait payload must agree before ROM trial.
