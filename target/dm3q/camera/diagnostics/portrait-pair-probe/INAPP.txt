Geometry/timing profile (requires the updated ROM Camera containing portrait-geometry-v2):
  python3 target/dm3q/camera/diagnostics/portrait-pair-probe/arm-inapp.py --serial R5CW72R7SDF --geometry --save-frames

Aim the rear cameras at a stationary, detailed, well-lit scene with objects at
several distances. Hold the phone still or mount it. Open Camera -> Settings
normally, keep Settings foreground for15 seconds, and avoid moving subjects.
The profile requests zoom10 first, then zoom1 after5 seconds of streaming.
Zoom1 tests whether explicitly bound physical outputs can provide their native
fields; it does not guarantee uncropped output. Actual result crops and samples
must confirm that. No physical crop override or vendor tag is injected.

--geometry alone records metadata only. --save-frames is a second explicit opt-in
that saves at most two grayscale PGM samples per physical output per phase
(up to eight total) in Camera's private report directory. It preserves luma plane
strides and records timestamps and filenames. Samples can contain personal scene
content; point at a suitable test scene. They remain private until collected and
are not automatically deleted. Grayscale samples establish framing, not still
capture quality. Never treat arrival_phase as authoritative across a transition:
match the image timestamp to the logical result and its request tag on the host.
The armer rejects geometry options on the installed older helper before creating
a marker; a rebuild/install of this source is needed for these new options.

Controlled profile v3c (temporary APK supported; no full ROM build required)
  arm-inapp.py --serial R5CW72R7SDF --controlled --save-frames

Keep Camera Settings foreground for32 seconds. Three phases at the lowest
jointly advertised fixed10..30fps range: auto AF/AE; then manual common30ms
exposure (clamped to supported ranges), low ISO800 and per-lens focus frozen
from each lens's last focused AF result; then a31-slot ISO800/3200 pulse code.
Values are clamped to common supported ranges. The pulse varies logical ISO
and requests a different physical auxiliary code so ignored physical overrides
are detectable. A small auxiliary focus perturbation also tests physical focus
control. Fixed-focus fallback0.5diopters is diagnostic only if no AF lock exists.
No lens is assumed to focus at3m; the device marks focus calibration approximate.
A detailed well-lit target around1..1.5m can be used if both lenses focus clearly.

Logs actual/requested AF, focus distance, ISO, exposure and frame duration;
per-image sampled luminance and edge statistics; up to two shared timestamps
per phase saved as both physical grayscale images (maximum12 PGMs). Individual
capture/result/image association is retained. Marker consumption, foreground
checks, pause/destroy stop and normal unarmed behavior remain unchanged.

analyze-controls.py ARCHIVE --calibration REAL_T1T2_FILE
requires an isolated host Python environment with numpy and OpenCV. It reports
AF/control acceptance, brightness/ISO correlation over candidate frame offsets,
SIFT correspondences and empirical fundamental-matrix inliers. It audits real
calibration intrinsic-to-crop/output mappings only when enough correspondences
exist. It does not equate an empirical F matrix with validated factory pose,
apply an assumed distortion transform to YUV, invent transform direction, or
claim a generated depth map. Focus metadata must be checked against image detail.

The connected ROM rejects adb Camera updates with DUPLICATE_PERMISSION owned
by AR Emoji. Do not remove that app or permission to bypass it. The tested
route stages a same-certificate APK and temporarily bind-mounts only Camera's
APK in the global namespace, verifies the zygote view, force-stops/restarts only
Camera, then unmounts and verifies the original hash. No persistent module,
reboot, data clearing or system-image write. Preserve rollback before mounting.
The experimental package preserves installed Camera DEX1..4, optimized resources,
manifest and native libraries; only diagnostic classes5.dex and signatures change.

Cross-frame geometry audit (2026-11-08)
  validate-pair-geometry.py ARCHIVE --output NEW_REPORT.json

Uses the same host numpy/OpenCV environment as analyze-controls.py. Fits an
empirical fundamental matrix on each complete pair and evaluates it on the
OTHER saved pairs with identical recorded crop/output size. Held-out descriptor
matches are not filtered with the matrix being evaluated. Reports all matches,
image/report hashes, symmetric residuals and competing planar-homography support.
The output must be a new file. This reads existing captures; no Camera APK
rebuild, phone access or calibration changes are involved.

Cross-frame agreement is an additional diagnostic only: repeated scene points,
planarity, false matches, focus changes and motion can confound it. A fitted
matrix never substitutes for the factory T1-T2 transform. The saved v3c run has
much weaker cross-phase agreement than its individual RANSAC fits suggest;
factory alignment, rectification and depth remain unvalidated.

Native calibration/crop audit (2026-11-08)
  python3 audit-calibration-crops.py ARCHIVE --calibration REAL_T1T2_FILE \
    --native-log ISOLATED_MODE4_LOGCAT --output NEW_REPORT.json

Requires only host Python. Uses the original physical-result crop and each
saved frame's intrinsic metadata. The real760-byte candidate has supplementary
camera values at0x114/0x11c, Tilt at0x124 and Shift at0x130. The isolated stock

Native geometry consumer audit (2026-11-08)
  python3 validate-native-transform.py ARCHIVE --calibration REAL_T1T2_FILE \
    --correspondences EXISTING_TELE_PAIR_HELDOUT.json --output NEW_REPORT.json

Requires numpy/OpenCV. Reads only existing captures; checks report/image hashes,
uses the exact real per-unit calibration hash and refuses output overwrite.
Reproduces recovered centered crop, Rodrigues radians and six-term odd/even
radial math with float64 host arithmetic. Self-checks cover zero/known rotation,
signed crop rounding, polynomial expansion and forward/inverse radial closure.
No native ABI or complete rectification pipeline is implemented.

The normal native map sets main rotation identity and aux Rodrigues(-Tilt).
It does not baseline-align from Shift. The host epipolar check explicitly
assumes Shift is t in X_aux=Rodrigues(Tilt)*X_main+t; this remains unvalidated.
Report all descriptor matches and a separately labelled scene-derived subset.
Never fit/select factory parameters from those points. Compare both assumed
input domains without selecting a winner. Both fail on the saved captures.
Alternate11-sample distortion tables, dynamic focus/OIS geometry and native
runtime branch selection remain unresolved. No ROM/APK/device changes occur.
