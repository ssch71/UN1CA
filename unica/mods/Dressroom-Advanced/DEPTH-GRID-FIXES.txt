Depth correction
----------------
The native port wrapped AbsClockView.draw(Canvas) but omitted dispatchDraw(Canvas).
Android can render a FrameLayout's children directly through dispatchDraw when
recording a container display list. The editor DepthFrameLayout already covered
that path, and upstream intercepted both paths. The generator now emits both
methods with balanced success/exception cleanup. The existing nested-draw guard
prevents applying the mask twice. Original Samsung method bodies/registers are
unchanged; both added wrappers use locals2.

This is a proven missing integration path and a strong explanation of the
preview/runtime difference. The exact draw path executed by this device was
not traced, so visual repair still requires testing the rebuilt candidate.

Grid correction
---------------
The editor's metrics callback could read the provider's stale committed4x1 grid
and overwrite its draft4x2 model. Structural edits also needed to restore the
model before native recalculation. Custom-grid boundaries now derive columns
and rows from the same draft used for native capacity. Scale-only changes
continue to use Samsung's native capacity. Production boundary sizing is
centralized in WidgetBoundaryMetrics.

A preview Bundle is scoped to the exact active size-manager object; a separate
plugin helper is synchronized only when its loaded Class differs. Separate
helper ClassLoaders were a possible confounder, not an observed runtime cause.
A log records that conditional branch if used. Preview overrides clear on
Apply, cancel/reset, owner changes and layout transitions; committed settings
are still written only after successful native Apply.
