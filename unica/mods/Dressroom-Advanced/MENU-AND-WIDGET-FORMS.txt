Why the clock menu closed while selecting controls
--------------------------------------------------
The previous observer compared MotionEvent raw screen coordinates with
getGlobalVisibleRect bounds in the floating window's coordinate space. It also
closed the parent unconditionally on ACTION_OUTSIDE, including events related
to option windows. That allowed an inside control click to be treated as outside.

Clock Advanced and Widget/Extras Advanced now use the same controller. It
converts clipped bounds to screen coordinates, includes native header areas,
tracks outside taps separately from drags/pinches and leaves inside taps alone.
Option dialogs own their own outside touches. Explicit color/size dialogs,
focused dropdowns and keyboard touches are protected from parent dismissal.
Flags/tracking clear on detach, hidden panes and editor reset; queued callbacks
from a closed session cannot reactivate the observer. Native close failure keeps
tracking available for retry. Closing a settings panel still retains its editor
draft; only Samsung Done/Apply commits it.

------------------

The left/right forms each consume2 columns and2 rows. Four columns cannot fit
2+1+2 columns. Scaling the whole group does not create these independent layouts.

Three missing parts have been corrected:
1. Samsung's picker filtered out two-row providers on phones. One exact picker
   callsite now admits them only for the active lockscreen Custom-grid draft
   with at least2 rows; no framework-wide tablet/device override is installed.
2. GridItem span changes alone did not select the actual provider layout.
   Supported forms now update Samsung's real semWidgetSize/span options and
   rebind the same appWidgetId with cloned provider metadata. Existing widget
   component, configured location/calendar and other options are preserved.
3. Native host wrapper target spans stayed at their constructor values. An exact
   AOD patch makes those two fields writable and adds a span setter, reusing
   native configuration sizing. Original methods/register counts are preserved.

Widget Advanced now offers Individual widget sizes. It lists only sizes declared
by each installed provider. Month Calendar declares2x2. Detailed Weather declares
2x1 and2x2; Simple Weather declares only1x1. Enlarging Simple Weather cannot
produce detailed Weather's extra content. Select the detailed provider initially.
Pinch resizing snaps to supported forms. Empty cells/grid boundaries constrain
placement; the explicit size chooser can change width and height independently.

Use after rebuilding
---------------------
Enable Widgets -> Advanced -> Custom grid; choose5x2 or larger. Add Month Calendar,
detailed Weather and two small widgets using Samsung's picker. Set the calendar
and weather to2x2 in Individual widget sizes, then drag them left/right and place
the two1x1 widgets in the middle. Move nearby widgets first if resizing would
overlap them. Apply normally, then reopen to verify persistence.

Preview and Cancel
-------------------
Provider options are real external state even before Done. Original provider
metadata/options are captured only for the exact active preview manager/host.
Cancel/session reset restores the original form; successful Apply discards the
rollback snapshot. Runtime refreshes are not entered into the preview rollback
registry. No provider/component swap, appWidgetId deletion/reallocation or app
configuration reset is performed. Cleanup failures are contained per host.
