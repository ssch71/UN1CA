Fixes in this candidate
----------------------
1. Masks: the provider now receives file-close callbacks on a dedicated HandlerThread.
   Previously it posted to DressRoom's main Looper while Apply synchronously
   waited for the mask on that same thread. This port-specific deadlock was
   reproduced with the production provider and simulated Android close dispatch.
   Upstream's provider was in a separate app process. Hash/size validation,
   atomic publication, bounded failure reporting and retry cleanup remain.
2. Widgets: stock item gestures reach Samsung's native handler. With Custom grid
   enabled, dragging a widget changes its real GridItem cell coordinates, and
   pinching changes its width/height in cells. Occupied cells and grid boundaries
   constrain placement; this is not arbitrary overlapping pixel placement.
   Pinching from the boundary rim changes the existing saved group scale
   (50-200%); dragging the rim or empty space moves the group. Use the grid
   columns/rows controls to add available cells. Per-item pinch is an addition
   beyond the upstream module's group drag/scale controls.
   An attached-preview registry recovers the correct Activity's widget owner
   before opening Advanced; it does not fabricate a blank editor owner.
3. Outside-dismiss: Advanced requests outside events from Samsung's floating
   panel window and calls Samsung's normal hidePanel(false). Embedded layouts
   also observe outside taps without replacing Samsung's normal gesture handling.
   Drags/multitouch do not count as embedded outside taps. Window flags are
   restored on tab changes, dismissal, detach and session cleanup. Widget gesture
   interception defers while the clock Advanced panel is visible.
4. Fonts: restoration checks the native Samsung stretch predicate AND the saved
   font ID/path, and excludes Display/import fonts. Stale height arrays cannot
   grant a different font stretch capability. Default native ID0 is valid.
5. Restored parity mappings: wallpaper-source change/setter callbacks, checkpoint
   before configuration changes, refresh after rotation, and date-visibility
   callbacks on six concrete AOD clock styles. These reuse existing helpers.
6. The pre-existing blur patch fix that isolates semSetBlurInfo conversion in a
   private helper is preserved; it prevents clobbering live null/Throwable caller
   registers. Unrelated source modifications remain untouched.

Why the first Samsung font stretches
-----------------------------------
Upstream also restricts dynamic per-digit stretching to supported native fonts.
Its README explicitly distinguishes imported-font axes from Samsung stretching.
The exact Samsung native predicate accepts IDs0,800-805,812,813. The first default
native clock choice can therefore be stretch-capable despite its plain thumbnail.
The user confirmed Use Display font was OFF. That observation alone is not proof
of an incorrect override: depth can retain the native font's current shape.
Mask occlusion can put an ordinary clock behind a subject without stretching it.
No arbitrary-font stretching was enabled. Use Display font and UN1CA's font bank
remain available; variable controls still follow the selected file's real axes.

Current intentional differences from upstream
--------------------------------------------
* Fixed APK callbacks replace LSPosed interception and dynamic version discovery.
  This targets the inspected dm3q SDK37 APKs, rather than the module's wider ABI set.
* Use Display font adds Samsung/UN1CA's applied display font as a clock backend.
  Imported TTF/OTF/TTC selection and per-font axes are retained.
* Profiles/fonts/masks belong to DressRoom's private encrypted data. Clock,
  Widgets and Extras commit together in atomic JSON after successful native Apply.
  Upstream uses its separate app/provider and separate profile commits.
* New individual widget drag/pinch gestures extend the upstream group controls.
* External-module settings and imported files are not automatically migrated.
  Legacy preference/orientation/fold migrations and fold-specific delayed
  wallpaper rebinding are not ported. dm3q has no fold screen.
* Upstream glyph-font request reuse and text-path memoization optimizations
  are absent. This is a potential performance difference, not evidence of a
  missing visible effect. Direct callbacks remove hook-installation machinery.
* Runtime parity remains unproven: only hardware testing can establish actual
  editor/lockscreen/AOD visuals, wallpaper motion, media transitions and power use.

Existing-mod interactions
-------------------------
DressRoom Ambient Weather gate and UN1CA font-bank patch are retained. AOD font
synchronization/backfill and lockscreen clock-style synchronization are retained.
Old competing height/normalization and fixed widget-grid overrides remain skipped
in the native-full path. VisualCloudCore/Ambient Weather fixes are unchanged.
Dynamic Island can duplicate charging/media information with enabled Extras.
External clock/depth/widget/Now Bar hooks can compete with the native port;
LockStar/ClockFace and replacement clock providers remain device-unverified.
