Native Now Nudge — dm3q ROM build integration

Photo/calendar POC: native patch stack now includes 0005-0006. This adapter has
its own default-off setting; see CONTEXT-ACTIONS.txt for activation, exact APK
build, on-device evidence, WhatsApp package policy and remaining limitations.

Enabled by default for dm3q in config.sh; other targets default off.
Do not enable the old UNICA_ENABLE_AIOSKERNELSERVICE donor path or the unsafe
S26U QNN experiment for this backend. Keep SamsungAiCore and Qwen fallback.

From repository root:
  source buildenv.sh dm3q
  bash unica/mods/rezoss/aioskernel/native-now-nudge/validate_rom_packaging.sh
  make_rom -f -r

The build applies the four new SmartSuggestions patches after existing 0026,
compiles NativeReplyBridge and backend Java, packages the pinned V73 native
runtime and checks/reconstructs the PTE/tokenizer payload. APKs use the ROM's
selected platform key. The backend versionCode is 142801205 and versionName
remains numeric 1.4.28. Native libraries are also laid out beside the system
APK; the runner has executable metadata.

The model/tokenizer live at /system/etc/unica/now-nudge-v73 (about 690 MiB).
There is no private model-data copy on first boot. The native runtime adds
roughly another 44 MiB including libraries beside and inside the APK.
The payload uses 50 MiB numeric chunks for repository storage.

OfflineLanguageModel_stub stays in the ROM. Install/update the full package
later as usual; the tested version is 4.0.01.24 / 400124010. The currently
installed full package passed the Samsung contextual-reply path. No extra
language-app gate patch was needed for that test. This does not make its
Samsung Gauss V81 weights work on V73 or enable vision, MT5 or semantic tasks.

On boot ro.unica.now_nudge_v73=1 selects the AIOS-enable branch and initializes
absent rezoss_aios_v73_backend and rezoss_now_nudge_native settings to 1.
Existing explicit settings of 0 are preserved. After flashing, verify:
  /mnt/c/platform-tools/adb.exe shell getprop ro.unica.now_nudge_v73
  /mnt/c/platform-tools/adb.exe shell settings get global rezoss_aios_v73_backend
  /mnt/c/platform-tools/adb.exe shell settings get global rezoss_now_nudge_native
  /mnt/c/platform-tools/adb.exe shell dumpsys package com.samsung.android.aioskernelservice
  /mnt/c/platform-tools/adb.exe shell dumpsys package com.samsung.android.offline.languagemodel
Expected property/settings 1, AIOS versionCode 142801205, full language version
400124010 active after its separate update. A data-installed SmartSuggestions
update can take precedence over the ROM APK; inspect pm path when testing.

To return replies to the older route without uninstalling other features:
  /mnt/c/platform-tools/adb.exe shell settings put global rezoss_now_nudge_native 0
  /mnt/c/platform-tools/adb.exe shell am force-stop com.samsung.android.smartsuggestions
For a ROM without this integration, set the dm3q default in config.sh to false
and force a clean rebuild. Keep the backend setting enabled with this minimal
AIOS build; its disabled path is not a stock donor runtime.

compile/sign/ZIP/alignment checks; real ADD_TO_WORK_DIR/SET_METADATA/SET_PROP

Existing data-APK runtime success does not establish those ROM checks.

Flashed-ROM diagnosis on 2026-10-15 found an execute_no_trans denial for the
runner's original shared-library label. integrate_rom.sh now labels this
executable system_file, while other libraries stay system_lib_file. A live
controlled-copy test passed preload and a Samsung handler reply (6642 ms),
with SELinux enforcing. See ROM-RUNNER-LABEL-FIX.txt. Rebuild/flash is required
to make that metadata correction permanent. The real messaging UI and battery
comparison remain unverified.

2026-10-15 follow-up: the corrected system runner now generates successfully,
but a real 53-token request took 20.3 s end to end. SmartReplyResolver released
SmartReplyer at its separate stock 10 s latch wait, before the successful SCS
callback arrived. Patch 0004 extends the inner wait to 45 s and the opt-in
outer notification wait to 55 s. Stock-route waits remain unchanged. This
fixes premature release; it does not speed up generation or prove UI delivery.
The safety_check error in this trace fell back to Samsung's rule-based filter
and the language service reported Success, so it was not the blocking error.

Additional live prerequisite: HoneyBoard's own Suggested replies preference
must be enabled. Global Now Nudge flags alone do not enable it. The provider's
suggested_replies_state was false on the tested phone, despite package allow,
feature support, Samsung Account and language gates passing. Enabled using the
keyboard's actual preference setter and verified provider/handler flags true.
Do not patch that provider to force true or bypass account checks. After a
SmartSuggestions restart, close/reopen the conversation to create a fresh
content-capture session; resuming the same Activity may retain a stale session.
