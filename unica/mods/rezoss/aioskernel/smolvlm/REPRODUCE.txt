SmolVLM-500M / S23U isolated QNN V73 runner and Samsung Binder wire adapter
======================================================================

This directory is an opt-in experiment. It is not invoked by customize.sh and
does not replace Samsung's AIOSKernelService package or change the ROM image.
The companion package is io.mesalabs.rezoss.vision. Its service implements the
Samsung inference transaction (8), original task/priority/image parcelables,
completion/failure/cancellation callbacks, and task cancellation. Unsupported
service/task transactions throw UnsupportedOperationException.

Prerequisites: Ubuntu/WSL, Python 3.11+, venv, Git, CMake, Ninja, Java, zip/unzip,
patch, Android SDK build-tools 37.0.0, platform android-37.0, NDK 28.2.13676358.
The connected phone must be the S23U; deployment uses the configured adb.exe.
Provisioning the companion's private model files requires the existing root.

Build from source (several GB of downloads and build space):

  cd /home/rezoss79/dev/sembilan
  source buildenv.sh dm3q
  ROOT="$SRC_DIR/unica/mods/rezoss/aioskernel/smolvlm"
  BASE=$(mktemp -d /tmp/rezoss-smolvlm.XXXXXX)
  python3 "$ROOT/fetch_sdk.py" "$BASE/sdk"
  export QNN_SDK_ROOT="$BASE/sdk"
  "$ROOT/build_runner.sh" "$BASE/runner"
  python3 "$ROOT/fetch_models.py" "$BASE/runner/models"
  python3 "$ROOT/fetch_fixtures.py" "$BASE/runner/inputs"
  "$ROOT/run_isolated.sh" "$BASE/runner" "$BASE/runner/inputs/bus.jpg"
  "$ROOT/run_isolated.sh" "$BASE/runner" "$BASE/runner/inputs/dog.jpg"
  "$ROOT/build_bridge.sh" "$BASE/runner" "$BASE/RezossVisionProbe.apk"
  "$ROOT/install_probe.sh" "$BASE/runner" "$BASE/RezossVisionProbe.apk"

The test signing key is kept at runner/vision-test.jks so later companion
updates can use the same identity. APK assembly directories stay in /tmp.
Models and SDK libraries are downloaded locally, not tracked as ROM source.
The community export's README does not establish redistribution rights;
retain the original SmolVLM Apache-2.0 license and check QAIRT terms before
redistributing packaged runtime libraries. This experiment only builds locally.

Device Binder tests (original Samsung Proxy, real cross-process Binder):

  ADB=/mnt/c/platform-tools/adb.exe
  "$ADB" shell am start -S -n io.mesalabs.rezoss.vision/.ProbeActivity --es image bus --es mode inference
  "$ADB" shell "su -c 'cat /data/user/0/io.mesalabs.rezoss.vision/files/probe-bus-inference.txt'"

Wait until the result starts CALLBACK, rather than STARTING, before another test.
On the tested S23U completion normally took approximately 2-14 seconds, depending
on process state. The worker timeout is 120 seconds. Screen-off execution uses
a foreground notification for the duration of pending inference.

  "$ADB" shell am start -S -n io.mesalabs.rezoss.vision/.ProbeActivity --es image bus --es mode cancel
  "$ADB" shell "su -c 'cat /data/user/0/io.mesalabs.rezoss.vision/files/probe-bus-cancel.txt'"
  "$ADB" shell am start -S -n io.mesalabs.rezoss.vision/.ProbeActivity --es image bus --es mode bad-input
  "$ADB" shell "su -c 'cat /data/user/0/io.mesalabs.rezoss.vision/files/probe-bus-bad-input.txt'"

Expected: callback 1 with bus-related text, callback 4 for cancellation, and
EXPECTED_REJECTION for missing image. The cat fixture is a known accuracy failure:
the quantized pipeline calls it a dog in snow; retain that negative result.
Cold timings and exact captions can differ with Android scheduling/preprocessing.

Native model compatibility repairs, applied only to the scratch ExecuTorch tree:

  legacy-context-header.patch: accepts the old unpadded 20-byte context header
    only when the declared binary length exactly matches the available bytes.
  legacy-mask-rank.patch: supports the export's rank-3 attention mask, retaining
    support for rank-4 and rejecting invalid dimensions before allocations.
  legacy-float-io.patch: explicitly marshals the export's declared FP32 decoder
    I/O to native UFixed16 using each QNN tensor's scale and offset. Enabled by
    REZOSS_LEGACY_FLOAT_IO=1 in the isolated runner/companion only. Missing opt-in
    fails instead of interpreting quantized bytes as floats.

Input contract of the companion subset: exactly one PromptTensor and one
ImageTensor, batch=1, channel=3, unsigned RGB NHWC bytes tagged INT8, supplied
through SharedMemory or byteData. Maximum 4096 per dimension and 4M pixels.
Images resize to 512 square and normalize (RGB/255 - 0.5)/0.5 into NCHW FP32.
The CLI helper uses Pillow LANCZOS; the Android adapter uses Bitmap filtering.
The result preserves prompt IDs and the input prompt name; it contains one text
PromptTensor. Token IDs are empty because the CLI does not expose them.
There are completion callbacks, not token streaming. Requests run serially,
with one queued request, cancellation, caller-death cleanup, and a timeout.

Boundary of this proof:

The original APK's classes.dex is included unchanged for its real Parcelable
implementations and client Proxy. No original smali is edited. The companion
service has a distinct component and a signature-only test permission. The
probe uses the same APK in a separate process; it traverses actual Binder and
the original Samsung Proxy rather than calling a local Java implementation.

Samsung applications are NOT automatically redirected to this component.
Their original model/session initialization, discovery, permissions, output-name
expectations, and feature-specific client flow still need integration tests.
Do not deploy this as a drop-in AIOSKernelService or fake successful Gauss/VIT
model loading. VIT embeddings, semantic tasks, MT5 and LVM image generation
remain separate pipelines and are unsupported by this image-to-text adapter.
