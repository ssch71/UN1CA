Update behavior
---------------
Compatibility now follows the GPU capability contract, independently of port
ROM version, firmware release name, module metadata, whole-driver checksum and
whole-DTB checksum. The runtime parser finds the GPU subtree by exact FDT path,
resolves property names from the current string table and checks Kalama v2 /
Gen7-2-1, ten DDR bus entries and the supported two-bin/SKU/property schema.
The fixed 2988-byte edit capacity and 96 MiB partition bounds remain unchanged.
No board label or DTB offset is used as a firmware version gate. FDT sections,
tokens, depth, duplicate properties, subtree boundaries and NOP padding are
checked before writing. Valid unrelated DTB changes are accepted and preserved.

native/driver.h compares the four audited functions' exact code plus relocation
identities, resolving relocated property strings instead of relying on their
file offsets. This accepts module metadata, signing and unrelated code changes
while retaining the observed row/SKU/RPMh/bus contract. It is intentionally not
a whole-driver equivalence claim: called helpers, hardware/command-DB behavior
and stability can vary. Changed critical code still needs review. The earlier
exact AZZI8 module is accepted as a legacy fallback; new firmware names do not
need to be registered. No catalogue of firmware/image pairs is used.

AZZI8 rollback images remain readable and archivable after GZIF. The clean
baseline check compares the known logical stock tables, independently of string
offsets/padding. Different future stock values need review; an unknown tuned
subtree cannot silently become a clean rollback baseline. Every full-image hash,
archive receipt, restart/renewal journal and mandatory NEW rollback export gate
remains enforced. Updates never auto-apply a saved profile or flash older
firmware to enable Apply. Shared logical profiles use the current FDT names.

Read-only build preflight applies the same capability parser to staged images
and modules, including footer-stripped build inputs. No firmware, target image,
SELinux rule or device partition was modified during diagnosis or validation.

Artifacts inspected (read-only)
------------------------------
Firmware: out/fw/SM-S918B_EUX/kernel/vendor_boot.img, S918BXXUAZZI8.
Driver: out/fw/SM-S918B_EUX/vendor_dlkm/lib/modules/msm_kgsl.ko.
SHA256: 16cb910e20983d9ff90c8eb11eb075310af50411d45853e7925282ac240f3ecc.
The out/target driver copy has the same SHA256; neither copy was modified.
REA/Ghidra 12.1.4 was used against the exact shipped ELF. Findings below are
static binary observations, not a successful modified-image boot or a voltage
measurement. ELF symbol values are section-relative (relocatable kernel module).

1. adreno_device_probe, .text+0x403f0, 3160 bytes:
   Reads qcom,gpu-pwrlevel-bins. Obtains feature code and, for applicable feature
   codes, pcode. Tries qcom,speed-bin, otherwise qcom,sku-codes, accepting an exact
   composite SKU or the zero wildcard. Parses the first matching table.
   Initial level must be inside the table; invalid values fall back to index 1.
   Initial minimum outside the table or below the initial/default index falls
   back to the last entry. The UI table selector does not force hardware SKU.
   REA evidence ev_fe43851503daa1b0a51397b6e5cbbe4c10ef49df710c4d2ed0e8ad7e96d0f718.

2. adreno_of_parse_pwrlevels, .text+0x4110c, 712 bytes:
   Reads reg, qcom,gpu-freq, qcom,level and DDR-type bus fields as u32 properties.
   Zero frequency is skipped. Indices >=16 are skipped/rejected by bounds checks.
   Stores voltage request at row offset 0x598, frequency at 0x580, using a 28-byte
   row stride. Reads optional qcom,acd-level and qcom,cx-level. Builds OPP entries
   from the frequency array if the OPP table is not already populated.
   The UI retains the inspected firmware's absence of cx-level editing. Unknown
   device-tree properties, changed SKU selectors and unrelated nodes are refused.

3. gen7_build_rpmh_tables, .text+0x9c6f8, 3012 bytes:
   Gets gfx.lvl, cx.lvl and mx.lvl auxiliary data from command DB.
   Adds an off-state slot and rejects a total DCVS count >16: at most 15 usable
   GPU levels per selected table. Converts frequency to kHz with integer /1000.
   Copies each voltage request into a u16 array. For GFX, scans the command-DB
   levels for the first entry >= the request; a request above the available range
   fails table construction. CX/MX votes are constructed separately.
   This is the reason raw requests 1, 16, 48, 72 and 96 can be represented without
   requiring them to occur in the stock GPU table. They are not direct mV values.
   A request 1 is not a standard named KonaBess corner. It will only work if the
   lookup finds an available corner, and need not yield a lower physical voltage
   than another request. Actual corner values are firmware/command-DB dependent.
   REA evidence ev_5aa34ed82cda3b8ac3669fc168254a2131022f9148660d5f7e3e0f6e26bd5a2b.

4. Exact source DTB:
   First DTB length 454042, DTB-set length 1808679.
   GPU-bin subtree offset within first DTB 160824, length 2988.
   Table 0 has 10 rows, initial/minimum 8/8; table 1 has 9 rows, 7/7.
   qcom,bus-table-ddr has 10 cells: indices 0..9. Active-row raw requests can
   exceed this range because the exact driver clamps them (see item 5). The
   final row bypasses that loop, so it must retain valid 0..9 bus indices.
   Table 0 default voltage requests: 224,192,144,128,80,64,60,56,52,52.
   The normalized entire DTB-set SHA256 remains
   99066fde3eede3bd5e17ba0a07182ebf06fda2fbf775003890c938af4e8fe23b.

5. kgsl_bus_init, .text+0x10660, 896 bytes:
   Loads the DDR-specific qcom,bus-table-ddrN if present, otherwise the default
   DDR table. For indices 0 through num_pwrlevels-2, frequency/max/min requests
   >= num_bus_levels are logged and replaced with num_bus_levels-1; min above
   max is repaired to max. The final power-level row is excluded from this loop.
   The editor therefore retains raw u32 requests on non-final rows with red
   warnings explaining the clamp, but requires 0..9 on the final row. Raw
   min<=frequency<=max remains a parser guard. This is observed behavior of the
   pinned driver, not a claim that other firmware safely clamps the same way.
   REA evidence ev_ec96141c882175919d1aa9a881336da0e5a635841a1663062b30b4b699adad49.

Upstream comparison
-------------------
KonaBess commit ff387dc7f630d7460c7a6561f83f71846217ee27:
https://github.com/libxzr/KonaBess/blob/ff387dc7f630d7460c7a6561f83f71846217ee27/app/src/main/java/xzr/konabess/ChipInfo.java

256,288,320,336,384,400,416,432,448,464,480. These are UI definitions, not proof

these choices plus raw 1, and accepts custom integer requests in 1..480.
ChipInfo.getMaxTableLevels returns a generic UI count of 16 for kalama; the
inspected Samsung Gen7 builder's extra off-state slot makes its usable bound 15.
ChipInfo.shouldIgnoreVoltTable returns true for kalama: this platform uses RPMh
requests in the frequency tables, not the app's separate OPP microvolt editor.
Non-stock values are RED; custom/raw values are experimental. The upper bound
480 is an editor guard based on upstream's named range, not a hardware promise.

GpuTableEditor.java edits headers and rows for multiple bins, can add/remove
levels and emits each row's property lines. TableIO.java exports chip/desc/freq
as konabess:// + Base64 + gzip JSON and imports the entire table text.
Our implementation does not execute imported DTS, invoke a shell, or run dtc.
It parses only the known Samsung table/header/row schema and fixed SKU lists.

What is implemented
-------------------
- Both inspected tables, 2..15 contiguous rows per table.
- Full positive u32 Hz frequency values; no forced 0.1 MHz rounding.
- RPMh requests 1..480, including 96/72/48/16/1; non-monotonic requests are
  representable, with warnings. No direct millivolt control is claimed.
- Existing initial/minimum selectors and bus fields; optional u32 ACD cells.
- Original KonaBess kalama exports and UN1CA profile v2, reviewed before loading.
- Stock/experimental warnings, red values and full before/after Apply review.
- Exact firmware, partition, driver, backup/export, journal and readback gates.

Intentional limits relative to upstream
--------------------------------------
The bins must fit the original 2988-byte subtree. Unused space is filled with
FDT_NOP, preserving every byte outside that region (except required AVB data).
This permits removal/replacement and additions when space is available; it does
not grow the DTB, repack the ramdisk, enlarge the image, or alter SKU selection.
The UI does not offer arbitrary properties, cx-level edits, extra bins, arbitrary
DTS includes/commands, other SoCs, or a separate OPP microvolt-table editor.
Header/driver/layout changes after an OTA still require compatibility review.
